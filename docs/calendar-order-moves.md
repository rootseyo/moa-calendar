# 캘린더 순서·기본 저장 위치·일정 이동

2026-10-14 운영 반영. 캐시 버전: 20261014-calendar-order-move-v2.

- 계정별 순서는 calendar_order 테이블에 저장한다. 새 캘린더는 기존 순서 뒤에 추가된다. 첫 번째로 편집 가능한 캘린더가 기본 캘린더다.
- 설정 → 캘린더 관리의 ↑·↓ 버튼은 PC·모바일·키보드에서 사용할 수 있다. 순서 변경은 다른 참여자의 목록에 영향을 주지 않는다.
- 일정 수정의 calendar_id는 대상이며, PUT 주소는 원본 캘린더다. 양쪽 편집 권한과 일정 버전을 확인하고, 기존 일정 ID·메모·색상·To Do·완료 상태를 보존한다.
- Google 가져오기 캘린더의 source_provider는 google로 저장하며 서버가 편집을 차단한다. 복사 화면과 Cmd+V는 기본 캘린더에 새 일정을 생성한다. 첫 항목이 읽기 전용이면 첫 편집 가능한 항목을 사용한다(사용자가 선택한 정책).
- 양방향 iCloud 이동은 원본 매핑을 calendar_move_jobs에 보존한 다음 로컬 이벤트를 이동한다. 원본 삭제가 성공하면 source_deleted를 저장하고 대상 동기화를 수행한다. 실패 시 30초마다 재시도하며 이벤트 수정은 완료까지 차단된다.
- 이동이 대기 중인 캘린더는 일반 pull을 건너뛴다. 이동과 pull은 external calendar 단위의 프로세스 잠금을 공유한다. 기존 단일 Node 프로세스 운영 범위를 유지한다.
- 외부 일정의 버전 충돌(412), 계정 인증 오류 등은 자동으로 덮어쓰지 않고 대기 상태와 오류를 일정 보기 화면에 표시한다.

## 검증

- 로컬 UI·순서 선택·이동 재시도·기존 설정 회귀 테스트 20개 통과.
- 별도 share_schedule_test_db의 HTTP 핸들러 통합 테스트 10개 통과. 순서 저장/타 사용자 격리, 이동 권한/버전 충돌, Google 읽기 전용, iCloud 원본 삭제 후 대상 실패/재시도/매핑 갱신을 검증했다. 외부 HTTP는 모의 응답으로 처리했다.
- CalDAV 모의 서버·동기화 테스트 5개 통과.
- 운영 화면에서 순서 변경 버튼·기본 캘린더 표시, iCloud 일정 수정의 활성 캘린더 선택란, 복사 창 유지 및 기본 캘린더 자동 선택을 확인했다. 실사용 일정을 저장·이동·복사하거나 사용자의 실제 순서를 변경하지 않았다.
- 색상 버튼은 PC 10×10px를 유지하며 iCloud/Google 표시는 동그라미 안에 들어간다. 모바일 버튼 크기는 기존 18×18px를 유지한다.
- 모바일 실화면 검증 제한은 기존 기록과 동일하다.
